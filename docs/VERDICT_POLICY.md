# Политика вердиктов и таксономия доверия

Дата: 2026-09-27; ревизия 2026-09-30. Спецификация для TODO §1 («честность вердиктов»). Теоретические формулировки — в `docs/THEORY.md`;
здесь — правила, по которым оркестраторы четырёх систем превращают выходы агентов и оракулов в итоговый
вердикт и confidence. Правила детерминированы и применяются **после** reasoning-агента: LLM предлагает вердикт,
оркестратор проверяет его допустимость.

## 1. Уровни доверия к артефакту/утверждению (`trust`)

| trust | Что означает | Примеры сигналов |
|---|---|---|
| `refuted` | детерминированное свидетельство **против** | контрпример оракула (`grammar_incorrect`, `test_result.status == fail`), конфликт в LL(k)-таблице для заявленного k, невалидные символы грамматики, слово из доказательства не лежит в L по оракулу |
| `verified` | детерминированная **полная** проверка утверждения | LL(k)/strong-LL(k) тест данной грамматики (разрешим и полон), сертификат левой рекурсии для грамматики, Lean-доказательство со статусом `proved` (R-Lean), регулярность заданного regex/DFA |
| `bounded_pass` | детерминированная, но **ограниченная** проверка | оракул принадлежности прошёл на N словах до длины L; выборочная эквивалентность грамматик. Проверка накачки при нескольких p сама по себе не повышает доверие к общему non-CFL/non-DCFL утверждению |
| `well_formed` | только структура: поля есть, JSON разобран, слова распарсены | сегодняшний «verified» всех трёх claim/oracle-верификаторов |
| `not_verified` | проверка невозможна или поля отсутствуют | `not_applicable`, ошибки парсинга |

Потолок `well_formed` = 0.55 (до 2026-09-27 — 0.60): без машинной проверки уверенность не должна достигать порога 0.6, по которому
`tfl-eval` считает вердикт «уверенным» — live-прогоны на Haiku (dcfl-21 дважды: shallit, затем dcfl_pumping) показали, что структурно
корректные, но неинстанцированные деструктивные доказательства регулярно ложны. Уверенность ≥ 0.6 означает хотя бы ограниченную
машинную проверку (`bounded_pass`).

Порядок: refuted < not_verified < well_formed < bounded_pass < verified (для выбора «сильнейшего» свидетельства
`refuted` исключается, а не сравнивается).

Переименование в коде (шаг 1, S): везде, где верификатор сегодня возвращает `verified` за наличие полей, он
возвращает `well_formed`. `verified` остаётся только за детерминированными полными проверками (см. таблицу).
`issues_found` (dcfl) → `not_verified` при отсутствии полей и `refuted`, если найден контрпример.

## 2. Потолки confidence по доверию

| Основание вердикта | Максимальный confidence |
|---|---|
| `verified` | 0.98 |
| `bounded_pass` | 0.85 |
| `well_formed` | 0.55 |
| `not_verified` / только самооценка LLM | 0.40 (вердикт допускается лишь как `inconclusive`/`uncertain`) |
| есть неразрешённое противоречие (п. 3, R3) | 0.50 |

Самооценка LLM (`proof_verified`, собственный `confidence` reasoning-агента) никогда не поднимает confidence выше
потолка; она может только понизить его.

## 3. Правила гейта (применяются оркестратором к решению reasoning)

- **R1 — провал ≠ опровержение.** Неудача конструктивных агентов (`grammar_incorrect`, опровергнутый PDA/DFA,
  «не удалось построить») **не является** свидетельством деструктивного вердикта. После инверсии гипотезы
  деструктивный вердикт (`non_regular`/`non_cfl`/`non_dcfl`/`not_ll`) требует деструктивного утверждения с
  trust ≥ `well_formed`, не опровергнутого оракулом. Иначе — `inconclusive` (cfl/dcfl: verdict `null`, ll: `uncertain`,
  reg: `partial`) с confidence ≤ 0.40 и пометкой `basis: "constructive_failure_only"`.
  (Прецедент: `task_grammar_filter_49`, live-прогон 2026-09-26 — `non_cfl 0.92` после инверсии без деструктивного
  доказательства; вердикт оказался верным случайно, см. `docs/THEORY.md` §2.3.)
- **R2 — конструктивный вердикт только по проверенному артефакту.** `regular`/`cfl`/`dcfl`/`ll` допустимы, только если
  есть артефакт (DFA/regex/грамматика/PDA/LL-грамматика) с trust ≥ `bounded_pass`. Артефакт с контрпримером
  (`refuted`) запрещает конструктивный вердикт на этом раунде: retry (если бюджет есть) или `inconclusive`.
  Для LL Format 3 (вопрос о грамматике) LL(k)-таблица даёт `verified`; для Format 1/2 (вопрос о языке) — `bounded_pass`
  по выборочной эквивалентности L(G) с языком задачи (`is_grammar_equivalent_sample`), иначе `well_formed`.
- **R2-CFG — грамматика в самом определении CFL-задачи.** Если `language_spec.kind == grammar` и проверены
  все условия корректной КС-грамматики (множества символов, старт, одиночный нетерминал слева, допустимая правая
  часть), язык по определению равен L(G). Это полное положительное свидетельство `input_grammar: verified`,
  независимо от ответов агентов: итог `cfl`, confidence 0.98, с исходной грамматикой в доказательстве.
  Противоположный набросок агента не создаёт математической неопределённости. Правило не распространяется
  на `grammar_filter`: дополнительный фильтр может уничтожить контекстную свободу.
- **R3 — противоречие.** Если одновременно есть конструктивный артефакт с trust ≥ `bounded_pass` и деструктивное
  утверждение с trust ≥ `well_formed`, оркестратор ставит `contradiction: true` и сначала пытается снять его
  **перекрёстной проверкой (R3′)**. Если противоречие осталось: вердикт — за стороной с trust `verified` (потолок
  0.85); если ни одна сторона не `verified` — `inconclusive` (cfl/dcfl: verdict `null`, ll: `uncertain`, reg: `partial`)
  с confidence ≤ 0.50 и обоими доказательствами в отчёте. `bounded_pass` против `well_formed` **не** решает спор:
  выборочный оракул и LLM-доказательство ошибаются по-разному (прецедент: live-прогон `wwvvR` на Haiku 2026-09-27 —
  грамматика прошла 50 выборочных слов, доказательство Огдена верно утверждало «не КС», гейт отдал вердикт грамматике).
  `done` с confidence > 0.50 при неразрешённом противоречии запрещён; retry-планировщику передаётся задача разрешить
  противоречие.
- **R3′ — перекрёстная проверка (детерминированная).** При противоречии оракул принадлежности (по определению языка /
  грамматике задачи, не по артефакту агента) прогоняет: (a) слова-свидетели деструктивного доказательства
  (инстанцированные z при p ∈ {3,4} и накачанные слова uvⁱwxⁱy, которые доказательство объявляет ∉ L; примеры
  `intersection_examples`/`non_examples`; слова w, w′ леммы Ю; пары u, v Нероуда) через конструктивный артефакт
  (грамматику/ДМПА/DFA/LL-грамматику): если артефакт принимает слово, которое по оракулу ∉ L, или отвергает слово ∈ L —
  артефакт `refuted`, спор решён в пользу деструктивной стороны; (b) слова, на которых артефакт прошёл оракул, — через
  утверждения деструктивного доказательства (например, «uwy ∉ L»): если оракул говорит uwy ∈ L, доказательство
  `refuted`. Если обе стороны выдерживают перекрёстную проверку — противоречие остаётся (см. R3).
- **R4 — reasoning первичен, но проверяется.** Оркестратор берёт вердикт reasoning-агента и проверяет R1–R3.
  Нарушение → понижение: `done/<constructive>` при `grammar_incorrect` → `retry` (если бюджет) иначе `inconclusive`;
  `done/<destructive>` без деструктивного свидетельства → как в R1. Все понижения логируются в
  `result["verdict_gate"]` (см. п. 5).
- **R4′ — исчерпание ретраев.** Если предложение reasoning недопустимо, а бюджет ретраев исчерпан, гейт выбирает
  **сильнейшее допустимое основание** из имеющихся: деструктивное утверждение с trust ≥ `well_formed` (не refuted) ⇒
  деструктивный вердикт с потолком по его trust; конструктивный артефакт ≥ `bounded_pass` ⇒ конструктивный вердикт;
  иначе `inconclusive`. Статус `failure` зарезервирован для технических отказов (ошибки API, невалидный вход), а не для
  «reasoning ошибся стороной» (прецедент: live-прогон eval 2026-09-27 — cfl-07/cfl-12 закончились `failure 0.0` при
  наличии деструктивных доказательств `well_formed`).
- **R2′ — конструктивный сертификат для DCFL.** Утверждение «язык DCFL» допустимо (R2) только с исполняемым артефактом:
  явный ДМПА (состояния, переходы с ε-шагами, режим принятия). Детерминизм — синтаксическое свойство и проверяется
  полностью (не более одного перехода на (q, a, Z), и не сосуществуют переходы по ε и по букве при одинаковых (q, Z)) ⇒
  для самого свойства «детерминирован» trust `verified`; равенство языка — выборочно через собственный детерминированный
  симулятор `dcfl_system/lib/dpda.dpda_run` (понимает принимающие конфигурации `accept_configs`, см. ниже) против оракула
  языка задачи на словах сэмплера **и на полном переборе коротких слов** (все слова над алфавитом до длины k, где
  Σ_{i≤k}|Σ|ⁱ ≤ 3000, k ≤ 10) ⇒ `bounded_pass` (не менее 30 слов с определённым ответом оракула) / `refuted`. Точные дубликаты
  переходов (совпадают `to` и `push`) схлопываются до проверки детерминизма и симуляции — это не конфликт.
  Перед проверкой детерминизма выполняется **каноническая нормализация, не меняющая язык** (только при принятии по финальному
  состоянию): ε-переход из конфигурации (q, Z) в принимающее состояние-сток q_acc без исходящих переходов удаляется, а пара (q, Z)
  добавляется в множество **принимающих конфигураций**: слово принимается при исчерпании входа, если состояние принимающее или
  пара (состояние, вершина стека) — принимающая конфигурация. Равносильность: через такой ε-переход слово принимается тогда и только
  тогда, когда вход исчерпан в конфигурации (q, вершина Z) (сделанный раньше, переход заводит вычисление в сток без выходов); другие
  вычисления сток не затрагивает; ДМПА с принятием по (состояние, вершина) — обычный ДМПА (вершина стека дублируется в состоянии).
  Помечать q принимающим *безусловно* нельзя: q может встречаться и с другой вершиной (прецедент: live dcfl-04 — автомат для
  {aⁿbⁿcᵐ} с ε-переходами в `q_accept`; после нормализации он детерминирован, но неверен — лишний переход q0 —b→ q_b — и
  опровергается симуляцией словом «b» из полного перебора коротких слов; сэмплер такого слова не порождал). Нормализация
  фиксируется в details; прочие ε-переходы, сосуществующие с буквенными на тех же (q, Z), — недетерминизм ⇒ `refuted`.
- **R-Lean — формальное доказательство как уровень `verified`.** Файл для Lean 4 всегда составляется кодом: формулировка
  (тип алфавита, определение языка, утверждение теоремы) **генерируется детерминированно из IR** (`agent_system/lib/lean_ir.py`),
  LLM-формализатор пишет только тело доказательства; формулировка из вывода LLM никогда не используется (прецедент:
  `ll_system` выдавал `theorem … : True := by sorry`, который «компилируется»). Результат проверки (`type_check.py`):
  `proved` — компиляция без ошибок, без `sorryAx`, `#print axioms` ⊆ {propext, Classical.choice, Quot.sound}
  (`native_decide`/`ofReduceBool` не допускается) ⇒ trust `verified` (0.98) для доказанной стороны (регулярность или
  нерегулярность, КС или не КС, DCFL или не DCFL); `has_sorry`, `error`, `timeout`, `unavailable` — не свидетельство ни за,
  ни против (R1). Основания формулировок: REG — Mathlib (`Language.IsRegular`, `DFA.pumping_lemma`, Майхилл–Нероуд);
  CFL и DCFL — `langlib` (классы, лемма о накачке, Огден, замкнутость DCFL); LL(k) — не формализуется. Доказатель запускается
  только по явному запросу (это live-вызовы), проверка типов — локально в Docker.
- **R5 — сертификаты для «не LL».** Для вопроса о **грамматике**: полный LL(k)-тест (`is_ll_k`), сертификат левой
  рекурсии/неоднозначности → `verified`; без сертификата перебор k ≤ K даёт формулировку «не LL(k) при k ≤ K»
  (`max_k_checked`), confidence ≤ 0.85, вердикт `not_ll` только с этой оговоркой. Для вопроса о **языке** левая
  рекурсия грамматики — не свидетельство; нужен деструктивный агент (substitution / prefix_classes / ambiguity)
  с trust ≥ `well_formed` (R1).
- **R6 — регулярность (agent_system).** `test_result.status == pass` → `bounded_pass` (итог `success`, confidence ≤ 0.85,
  не 1.0); `fail` с контрпримером → артефакт `refuted` → конструктивный вердикт запрещён (R2), а не `failure 0.0`
  для правильного `non_regular`; деструктивное доказательство (pumping/Nerode) с `well_formed` → `non_regular` ≤ 0.55,
  с проверкой слов оракулом → ≤ 0.85; формальное доказательство со статусом `proved` (R-Lean: без ошибок, без `sorryAx`, стандартные аксиомы, перепроверка
  ядром) → `verified`.
- **R7 — ретраи читают оракул.** Планировщик ретраев получает `trust` по агентам; `refuted` артефакты попадают в
  `agents_to_retry` с контрпримером в hint (dcfl: заменить проверку `== "refuted"` на `trust == "refuted"`;
  `issues_found` без контрпримера — это `not_verified`, а не провал).

## 4. Шаг 2 — детерминированные семантические проверки (M)

Семантические проверки; их результат относится только к реально проверенному утверждению.
Формулировки и ссылки: [THEORY_REFERENCE.md](THEORY_REFERENCE.md).

- **cfl / parikh, stratification, filters.** Конечная выборка векторов всегда полулинейна;
  `looks_semilinear` — эвристика полного образа, а не сертификат. `is_semilinear=True`
  для корректной исходной CFG следует из теоремы Париха; дополнительный произвольный фильтр
  требует отдельного анализа. Для стратификации нужны доказанное ограничивающее выражение,
  точное множество всех показателей и существование стратифицированного представления.
  Пустая выборка не доказывает пустоту языка. Регулярность Boolean-комбинаций переносится
  от регулярных компонентов; нерегулярность так не переносится. Смешанные знаки в пороговой
  линейной сумме не допускают общего сокращения к ДКА.

- **cfl / pumping, ogden.** Инстанцировать `word_chosen` при p ∈ {3,4}; требуется |z| ≥ p, а для Огдена —
  не менее p отмеченных позиций. Проверить `z ∈ L`; точный ответ False опровергает это конкретное свидетельство.
  Перебрать разбиения (для обычной леммы |vwx| ≤ p, |vx| ≥ 1; для Огдена ограничения на отмеченные позиции)
  и искать выход из L при i ∈ {0,2,3}. Закрытие всех конечных проверок сохраняет **`well_formed`**: универсальный
  аргумент требует всех p, а у конечного L={a¹⁰} малые p=3,4 также закрываются. Выживание разбиения при трёх
  проверенных i тоже не опровергает универсальный аргумент: выход может произойти при i=4 или позже.
  Такой результат фиксируется как незакрытое разбиение, не `refuted`. Неизвестный ответ оракула (None/ошибка)
  не превращается в False и не создаёт отрицательное слово-свидетельство для перекрёстной проверки.
  `details.bounded_check` хранит диагностику и фактические границы перебора отдельно от trust.
  Для **closure_reduction** вложенная накачка проверяется относительно L ∩ R по тем же правилам;
  примеры/антипримеры пересечения допускают `bounded_pass` лишь при достаточном числе определённых ответов.
- **dcfl / dcfl_pumping.** Контракт требует `word_instances`: конкретные w = xy, w′ = xz при n = p + 2 (т.е. n > p + 1, как в
  рассуждениях THEORY.md §1.1) для p ∈ {2,3} (общий префикс x, |x| > p, первые буквы y и z совпадают). **Без инстансов trust не выше `not_verified`** (доказательство по лемме Ю,
  которое нельзя инстанцировать, не является доказательством; прецедент: live dcfl-21 — well_formed без инстансов на DCFL-языке).
  Значение n = p + 2 — требование промпта; код проверяет только |x| > p, общий префикс и совпадение первых букв y, z.
  С инстансами и оракулом: проверить w, w′ ∈ L; перебрать условие (1) — все пары (x₂,x₄) с |x₂x₃x₄| ≤ p, |x₂x₄| ≥ 1 (не более
  600 разбиений) — и условие (2) — x₂ в последних p символах x с |y₂|, |z₂| ≤ 4 (не более 3000 разбиений; превышение лимитов ⇒
  остаётся `well_formed`) — при i ∈ {0, 2, 3}: найдено разбиение, при котором оба накачанных слова остаются в L при всех
  i ∈ {0,2,3} ⇒ незакрытый случай, **не** `refuted`: для опровержения общего аргумента потребовалось бы
  установить выживание при всех i, а более позднее i может вывести слово из L. Если все разбиения при обоих p ломают хотя бы одно
  слово при i ∈ {0,2}, trust остаётся **`well_formed`** (проверено необходимое условие), а **не** `bounded_pass`: лемма Ю
  гарантирует разбиения лишь при p ≥ p₀, и при малых p условия закрываются и у DCFL-языков (прецедент: exam_04 — DCFL по
  THEORY.md §1.10, а ложное доказательство non_dcfl при p ∈ {2,3} закрывалось полностью). Разбиения, на которых оракул ответил
  «неизвестно», считаются незакрытыми. Брутфорс — как в `dcfl_system/tests/test_theory_contract.py` (exam_03), вынесенный в lib.
- **dcfl / shallit.** `nerode_classes` применима только если **все** классы Нероуда, включая мёртвый класс D, конечны
  (THEORY.md §1.2); «бесконечно много классов» — не аргумент (у {aⁿbⁿ} их бесконечно много, а язык DCFL). Контракт требует
  явное поле `dead_class_status ∈ {empty, infinite}` — третьего не дано: D замкнут относительно продолжений справа (x ∈ D ⇒ xΣ* ⊆ D),
  поэтому непустой D бесконечен, и «D конечен» означает D = ∅ (устаревшее значение `finite` читается как `empty`); `infinite` при
  status success ⇒ `refuted` (доказательство само признаёт технику неприменимой). Проверка по оракулу выполняется **всегда, когда оракул есть, независимо от вида
  разделяющего суффикса**: перебрать слова длины ≤ 8 и найти непродолжаемые (ограниченный поиск продолжений до +6 символов);
  `empty` и найдено мёртвое слово (поиск продолжений до 2|w|+2 символов; превышение бюджета ⇒ «неизвестно», слово пропускается)
  ⇒ только `unknown`: отсутствие продолжения в конечном окне не доказывает, что слово мёртвое. Например, ε
  продолжается до a²⁰ в регулярном языке {a²⁰}, но поиск до длины 6 этого не обнаруживает. Для `refuted` нужен
  точный сертификат отсутствия любого продолжения (полный алгоритм для Pref(L) или доказанная граница),
  а не эвристическая граница max(6, 2|w|+2). Затем инстанцировать разделяющий
  суффикс для 3–5 пар u ≠ v и проверить uw ∈ L, vw ∉ L (только если суффикс буквальный).
  Если проверка мёртвого класса осталась `unknown`, успешные пары не повышают общий trust выше
  `well_formed`: они не закрывают эту предпосылку. Если для каждого проверяемого префикса найдено
  конкретное продолжение, этот этап получает только `bounded_pass`, не доказательство D=∅.
  `prefix_continuation`:
  проверить 5–10 слов из `derived_language` на принадлежность L_$ (x ∈ L, xy ∈ L).
- **ll / оракул языка задачи.** Format 1 (`set_builder`) — word-оракул по спецификации; Format 2/3 (язык задан
  явной грамматикой) — точный CYK-оракул по этой грамматике (однобуквенные терминалы без `$`/`ε`; иначе оракула нет).
  Ответ `None` (нет оракула, исчерпан бюджет) — неизвестность, а не непринадлежность.
- **ll / constructive.** `validate_grammar_symbols` (терминалы ⊆ алфавита), затем `is_grammar_equivalent_sample`
  с языком задачи до длины 8 → `bounded_pass`/`refuted` (во всех трёх форматах, если оракул есть; совпадение выборки
  никогда не даёт `verified`); для Format 3 — полный LL(k)-тест данной грамматики → `verified`/`refuted`.
- **ll / substitution.** Инстанцировать `branch_words` при n = k + 2, k ∈ {1,2}: оба слова ∈ L,
  общая буквальная часть доходит до позиции n (в частности, окна длины k после позиции n−k
  совпадают) → `bounded_pass` при выполнении остальных проверок шаблона. Это не равенство
  FIRST_k хвостов после максимального общего префикса. Аргумент о выводе остаётся LLM-частью,
  потолок 0.85; `None` не опровергает принадлежность.
- **ll / prefix_classes.** Как shallit `nerode_classes` (с тем же правилом про мёртвый класс: без точного сертификата
  предпосылка остаётся `unknown`, итог не выше `well_formed`).
- **reg / pumping.** Инстанцировать семейство при p ∈ {2,3,4}; для каждого слова проверить все
  xyz с |xy| ≤ p, |y| > 0. Результаты при конечных p и i — только диагностика (`well_formed`):
  закрытие этих p не доказывает ∀p, а выживание при нескольких i не доказывает ∀i.
  `refuted` требует конкретного нарушения заявленной предпосылки, например z ∉ L.
  Ответ оракула `None` не является ни принадлежностью, ни непринадлежностью.
- **reg / nerode.** Проверка конкретных пар и заявленного различающего суффикса может дать
  `bounded_pass`/`refuted` для этих свидетельств; конечное число пар не доказывает бесконечность
  индекса. Пустой суффикс допустим. Неизвестная принадлежность оставляет проверку незавершённой.

Оракулы принадлежности (единая точка — `cfl_oracle_from_ir` в cfl, `build_membership_oracle_from_ir` в dcfl; dcfl импортирует
cfl): CYK по грамматике (`grammar` / `grammar_filter`), set_builder с `variables`, regex/DFA (reg) и **оракул экспоненциальной
нотации** (`cfl_system/lib/exponent_pattern.py`: шаблон из блоков `x^e`, условие — булева формула над линейными
(не)равенствами, `union`) для `natural`/`word_pattern`-строк вида {aⁿbⁿcᵐ | n,m ≥ 0}. Оракул экспоненциальной нотации
ограничен длиной слова и бюджетом перебора; вне ограничения он отвечает «неизвестно» (None), а не «нет», и такие слова
в семантических проверках пропускаются. Если оракул для IR не строится (перечень исключений —
`tfl_eval/tests/test_eval_oracle_coverage.py`), trust остаётся `well_formed`, и потолок 0.55 действует.

## 5. Формат результата

В `result` каждого пайплайна добавляются поля (без ломки существующих):

```json
"verdict_gate": {
  "basis": [{"agent": "closure_reduction", "trust": "bounded_pass"}],
  "contradiction": false,
  "downgrades": ["reasoning proposed done/cfl with grammar_incorrect artifact -> retry"],
  "confidence_cap": 0.85
}
```

и `trust` внутри каждого элемента `agent_results`/`claim_verification`/`oracle_verification`. Рендереры показывают
метку доверия словами (`проверено полностью` / `проверено выборочно` / `корректно оформлено` / `опровергнуто`);
зелёный баннер «verified» — только для `verified`.

## 6. Тесты политики

Для каждой системы — тест с моками, воспроизводящий сценарии:
1. конструктивный агент опровергнут, деструктивных доказательств нет, reasoning говорит `done/<destructive>` →
   итог `inconclusive`, confidence ≤ 0.40, `downgrades` непустой (сценарий grammar_filter_49 до правок);
2. конструктивный артефакт `bounded_pass` + деструктивное `well_formed` → `contradiction: true`, confidence ≤ 0.50;
3. `verified` (LL(k)-таблица / Lean `proved` по R-Lean) → confidence может быть 0.98;
4. только `well_formed` деструктивное доказательство → вердикт допустим, confidence ≤ 0.55;
5. reg: `test_result.fail` при `non_regular` → не `failure 0.0`, а R6.

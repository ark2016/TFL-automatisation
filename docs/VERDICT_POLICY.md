# Политика вердиктов и таксономия доверия

Дата: 2026-09-27. Спецификация для TODO §1 («честность вердиктов»). Теоретические формулировки — в `docs/THEORY.md`;
здесь — правила, по которым оркестраторы четырёх систем превращают выходы агентов и оракулов в итоговый
вердикт и confidence. Правила детерминированы и применяются **после** reasoning-агента: LLM предлагает вердикт,
оркестратор проверяет его допустимость.

## 1. Уровни доверия к артефакту/утверждению (`trust`)

| trust | Что означает | Примеры сигналов |
|---|---|---|
| `refuted` | детерминированное свидетельство **против** | контрпример оракула (`grammar_incorrect`, `test_result.status == fail`), конфликт в LL(k)-таблице для заявленного k, невалидные символы грамматики, слово из доказательства не лежит в L по оракулу |
| `verified` | детерминированная **полная** проверка утверждения | LL(k)/strong-LL(k) тест данной грамматики (разрешим и полон), сертификат левой рекурсии для грамматики, Lean-файл без `sorry` со статусом `valid`, регулярность заданного regex/DFA |
| `bounded_pass` | детерминированная, но **ограниченная** проверка | оракул принадлежности прошёл на N словах до длины L; накачка проверена для p ∈ {3,4,5} перебором разбиений; выборочная эквивалентность грамматик |
| `well_formed` | только структура: поля есть, JSON разобран, слова распарсены | сегодняшний «verified» всех трёх claim/oracle-верификаторов |
| `not_verified` | проверка невозможна или поля отсутствуют | `not_applicable`, ошибки парсинга |

Порядок: refuted < not_verified < well_formed < bounded_pass < verified (для выбора «сильнейшего» свидетельства
`refuted` исключается, а не сравнивается).

Переименование в коде (шаг 1, S): везде, где верификатор сегодня возвращает `verified` за наличие полей, он
возвращает `well_formed`. `verified` остаётся только за детерминированными полными проверками (см. таблицу).
`issues_found` (dcfl) → `not_verified` при отсутствии полей и `refuted`, если найден контрпример.

## 2. Потолки confidence по доверию

| Основание вердикта | Максимальный confidence |
|---|---|
| `verified` | 0.98 |
| `bounded_pass` | 0.85 |
| `well_formed` | 0.60 |
| `not_verified` / только самооценка LLM | 0.40 (вердикт допускается лишь как `inconclusive`/`uncertain`) |
| есть неразрешённое противоречие (п. 3, R3) | 0.50 |

Самооценка LLM (`proof_verified`, собственный `confidence` reasoning-агента) никогда не поднимает confidence выше
потолка; она может только понизить его.

## 3. Правила гейта (применяются оркестратором к решению reasoning)

- **R1 — провал ≠ опровержение.** Неудача конструктивных агентов (`grammar_incorrect`, опровергнутый PDA/DFA,
  «не удалось построить») **не является** свидетельством деструктивного вердикта. После инверсии гипотезы
  деструктивный вердикт (`non_regular`/`non_cfl`/`non_dcfl`/`not_ll`) требует деструктивного утверждения с
  trust ≥ `well_formed`, не опровергнутого оракулом. Иначе — `inconclusive` (cfl/dcfl: verdict `null`, ll: `uncertain`,
  reg: `partial`) с confidence ≤ 0.40 и пометкой `basis: "constructive_failure_only"`.
  (Прецедент: `task_grammar_filter_49`, live-прогон 2026-09-26 — `non_cfl 0.92` после инверсии без деструктивного
  доказательства; вердикт оказался верным случайно, см. `docs/THEORY.md` §2.3.)
- **R2 — конструктивный вердикт только по проверенному артефакту.** `regular`/`cfl`/`dcfl`/`ll` допустимы, только если
  есть артефакт (DFA/regex/грамматика/PDA/LL-грамматика) с trust ≥ `bounded_pass`. Артефакт с контрпримером
  (`refuted`) запрещает конструктивный вердикт на этом раунде: retry (если бюджет есть) или `inconclusive`.
  Для LL Format 3 (вопрос о грамматике) LL(k)-таблица даёт `verified`; для Format 1/2 (вопрос о языке) — `bounded_pass`
  по выборочной эквивалентности L(G) с языком задачи (`is_grammar_equivalent_sample`), иначе `well_formed`.
- **R3 — противоречие.** Если одновременно есть конструктивный артефакт с trust ≥ `bounded_pass` и деструктивное
  утверждение с trust ≥ `well_formed`, оркестратор ставит `contradiction: true` и сначала пытается снять его
  **перекрёстной проверкой (R3′)**. Если противоречие осталось: вердикт — за стороной с trust `verified` (потолок
  0.85); если ни одна сторона не `verified` — `inconclusive` (cfl/dcfl: verdict `null`, ll: `uncertain`, reg: `partial`)
  с confidence ≤ 0.50 и обоими доказательствами в отчёте. `bounded_pass` против `well_formed` **не** решает спор:
  выборочный оракул и LLM-доказательство ошибаются по-разному (прецедент: live-прогон `wwvvR` на Haiku 2026-09-27 —
  грамматика прошла 50 выборочных слов, доказательство Огдена верно утверждало «не КС», гейт отдал вердикт грамматике).
  `done` с confidence > 0.50 при неразрешённом противоречии запрещён; retry-планировщику передаётся задача разрешить
  противоречие.
- **R3′ — перекрёстная проверка (детерминированная).** При противоречии оракул принадлежности (по определению языка /
  грамматике задачи, не по артефакту агента) прогоняет: (a) слова-свидетели деструктивного доказательства
  (инстанцированные z при p ∈ {3,4} и накачанные слова uvⁱwxⁱy, которые доказательство объявляет ∉ L; примеры
  `intersection_examples`/`non_examples`; слова w, w′ леммы Ю; пары u, v Нероуда) через конструктивный артефакт
  (грамматику/ДМПА/DFA/LL-грамматику): если артефакт принимает слово, которое по оракулу ∉ L, или отвергает слово ∈ L —
  артефакт `refuted`, спор решён в пользу деструктивной стороны; (b) слова, на которых артефакт прошёл оракул, — через
  утверждения деструктивного доказательства (например, «uwy ∉ L»): если оракул говорит uwy ∈ L, доказательство
  `refuted`. Если обе стороны выдерживают перекрёстную проверку — противоречие остаётся (см. R3).
- **R4 — reasoning первичен, но проверяется.** Оркестратор берёт вердикт reasoning-агента и проверяет R1–R3.
  Нарушение → понижение: `done/<constructive>` при `grammar_incorrect` → `retry` (если бюджет) иначе `inconclusive`;
  `done/<destructive>` без деструктивного свидетельства → как в R1. Все понижения логируются в
  `result["verdict_gate"]` (см. п. 5).
- **R4′ — исчерпание ретраев.** Если предложение reasoning недопустимо, а бюджет ретраев исчерпан, гейт выбирает
  **сильнейшее допустимое основание** из имеющихся: деструктивное утверждение с trust ≥ `well_formed` (не refuted) ⇒
  деструктивный вердикт с потолком по его trust; конструктивный артефакт ≥ `bounded_pass` ⇒ конструктивный вердикт;
  иначе `inconclusive`. Статус `failure` зарезервирован для технических отказов (ошибки API, невалидный вход), а не для
  «reasoning ошибся стороной» (прецедент: live-прогон eval 2026-09-27 — cfl-07/cfl-12 закончились `failure 0.0` при
  наличии деструктивных доказательств `well_formed`).
- **R2′ — конструктивный сертификат для DCFL.** Утверждение «язык DCFL» допустимо (R2) только с исполняемым артефактом:
  явный ДМПА (состояния, переходы с ε-шагами, режим принятия). Детерминизм — синтаксическое свойство и проверяется
  полностью (не более одного перехода на (q, a, Z), и не сосуществуют переходы по ε и по букве при одинаковых (q, Z)) ⇒
  для самого свойства «детерминирован» trust `verified`; равенство языка — выборочно через симулятор
  (`cfl_system/lib/pda_simulator`, dcfl импортирует cfl) против оракула языка задачи ⇒ `bounded_pass`/`refuted`.
  Перед проверкой детерминизма допускается **каноническая нормализация, не меняющая язык**: ε-переход из (q, Z) в
  принимающее состояние-сток без исходящих переходов заменяется пометкой q как принимающего (при принятии по финальному
  состоянию слово принимается через такой переход тогда и только тогда, когда вход исчерпан в q, а другие вычисления сток не
  затрагивает); нормализация фиксируется в details. Прочие ε-переходы, сосуществующие с буквенными на тех же (q, Z), —
  недетерминизм ⇒ `refuted` (прецедент: live dcfl-04 — верный автомат для {aⁿbⁿcᵐ} с ε-переходами в `q_accept`).
  Словесная «стековая стратегия» без ДМПА — `well_formed` и по R2 не даёт вердикт `dcfl` (прецедент: dcfl-04/15/17 в
  live-прогоне eval — три верных DCFL остались `inconclusive`).
- **R5 — сертификаты для «не LL».** Для вопроса о **грамматике**: полный LL(k)-тест (`is_ll_k`), сертификат левой
  рекурсии/неоднозначности → `verified`; без сертификата перебор k ≤ K даёт формулировку «не LL(k) при k ≤ K»
  (`max_k_checked`), confidence ≤ 0.85, вердикт `not_ll` только с этой оговоркой. Для вопроса о **языке** левая
  рекурсия грамматики — не свидетельство; нужен деструктивный агент (substitution / prefix_classes / ambiguity)
  с trust ≥ `well_formed` (R1).
- **R6 — регулярность (agent_system).** `test_result.status == pass` → `bounded_pass` (итог `success`, confidence ≤ 0.85,
  не 1.0); `fail` с контрпримером → артефакт `refuted` → конструктивный вердикт запрещён (R2), а не `failure 0.0`
  для правильного `non_regular`; деструктивное доказательство (pumping/Nerode) с `well_formed` → `non_regular` ≤ 0.60,
  с проверкой слов оракулом → ≤ 0.85; Lean без `sorry` (`status == "valid" and sorry_count == 0`) → `verified`.
- **R7 — ретраи читают оракул.** Планировщик ретраев получает `trust` по агентам; `refuted` артефакты попадают в
  `agents_to_retry` с контрпримером в hint (dcfl: заменить проверку `== "refuted"` на `trust == "refuted"`;
  `issues_found` без контрпримера — это `not_verified`, а не провал).

## 4. Шаг 2 — детерминированные семантические проверки (M)

Минимальный набор, поднимающий trust с `well_formed` до `bounded_pass` / `refuted`:

- **cfl / pumping, ogden, closure_reduction.** Инстанцировать `word_chosen` при p ∈ {3,4,5} (парсер параметрических
  слов уже есть в `cfl_word_generator`/`_parse_word_pattern`-аналогах), проверить `z ∈ L` оракулом (CYK для грамматик,
  word-оракул для set_builder); перебрать все разбиения `uvwxy` с |vwx| ≤ p, |vx| ≥ 1 и проверить, что при i ∈ {0, 2}
  хотя бы одно накачанное слово ∉ L. Все разбиения закрыты → `bounded_pass`; найдено разбиение, где оба слова ∈ L →
  `refuted` (доказательство неверно для этого p). Для closure_reduction дополнительно: сэмплировать слова из
  `intersection_description` и проверить, что они ∈ L ∩ R.
- **dcfl / dcfl_pumping.** Инстанцировать w, w′ при n = p + 1 (p ∈ {2,3}), проверить w, w′ ∈ L, общий префикс и
  первые буквы y, z; перебрать пары (x₂,x₄) с |x₂x₃x₄| ≤ p и x₂ в последних p символах x для условия (2), как в
  `dcfl_system/tests/test_theory_contract.py` (уже есть брутфорс для exam_03) → `bounded_pass`/`refuted`.
- **dcfl / shallit.** `nerode_classes` применима только если **все** классы Нероуда, включая мёртвый класс D, конечны
  (THEORY.md §1.2); «бесконечно много классов» — не аргумент (у {aⁿbⁿ} их бесконечно много, а язык DCFL). Контракт требует
  явное поле `dead_class_status ∈ {empty, finite, infinite}`; `infinite` при status success ⇒ `refuted` (доказательство само
  признаёт технику неприменимой). Проверка по оракулу выполняется **всегда, когда оракул есть, независимо от вида
  разделяющего суффикса**: перебрать слова длины ≤ 8 и найти непродолжаемые (ограниченный поиск продолжений до +6 символов);
  `empty` и найдено мёртвое слово ⇒ `refuted`; `finite`, а мёртвые слова есть на каждой длине от 2 до 8 ⇒ `refuted`
  (ограниченное, но решающее свидетельство бесконечности D, как и другие R1-опровержения). Затем инстанцировать разделяющий
  суффикс для 3–5 пар u ≠ v и проверить uw ∈ L, vw ∉ L (только если суффикс буквальный). `prefix_continuation`:
  проверить 5–10 слов из `derived_language` на принадлежность L_$ (x ∈ L, xy ∈ L).
- **ll / constructive.** `validate_grammar_symbols` (терминалы ⊆ алфавита), затем `is_grammar_equivalent_sample`
  с языком задачи до длины 8 → `bounded_pass`/`refuted`; для Format 3 — полный LL(k)-тест → `verified`/`refuted`.
- **ll / substitution.** Инстанцировать `branch_words` при n = k + 2, k ∈ {1,2}: оба слова ∈ L, общий префикс и
  FIRST_k совпадают → `bounded_pass` (аргумент о выводе остаётся LLM-частью, потолок 0.85).
- **ll / prefix_classes.** Как shallit `nerode_classes`.
- **reg / pumping, nerode.** Инстанцировать слово/семейство при p ∈ {2,3,4}, проверить принадлежность и
  разбиения перебором (для регулярной накачки — все разбиения xyz, |xy| ≤ p) → `bounded_pass`/`refuted`.

Оракулы принадлежности (единая точка — `cfl_oracle_from_ir` в cfl, `build_membership_oracle_from_ir` в dcfl; dcfl импортирует
cfl): CYK по грамматике (`grammar` / `grammar_filter`), set_builder с `variables`, regex/DFA (reg) и **оракул экспоненциальной
нотации** (`cfl_system/lib/exponent_pattern.py`: шаблон из блоков `x^e`, условие — булева формула над линейными
(не)равенствами, `union`) для `natural`/`word_pattern`-строк вида {aⁿbⁿcᵐ | n,m ≥ 0}. Оракул экспоненциальной нотации
ограничен длиной слова и бюджетом перебора; вне ограничения он отвечает «неизвестно» (None), а не «нет», и такие слова
в семантических проверках пропускаются. Если оракул для IR не строится (перечень исключений —
`tfl_eval/tests/test_eval_oracle_coverage.py`), trust остаётся `well_formed`, и потолок 0.60 действует.

## 5. Формат результата

В `result` каждого пайплайна добавляются поля (без ломки существующих):

```json
"verdict_gate": {
  "basis": [{"agent": "closure_reduction", "trust": "bounded_pass"}],
  "contradiction": false,
  "downgrades": ["reasoning proposed done/cfl with grammar_incorrect artifact -> retry"],
  "confidence_cap": 0.85
}
```

и `trust` внутри каждого элемента `agent_results`/`claim_verification`/`oracle_verification`. Рендереры показывают
метку доверия словами (`проверено полностью` / `проверено выборочно` / `корректно оформлено` / `опровергнуто`);
зелёный баннер «verified» — только для `verified`.

## 6. Тесты политики

Для каждой системы — тест с моками, воспроизводящий сценарии:
1. конструктивный агент опровергнут, деструктивных доказательств нет, reasoning говорит `done/<destructive>` →
   итог `inconclusive`, confidence ≤ 0.40, `downgrades` непустой (сценарий grammar_filter_49 до правок);
2. конструктивный артефакт `bounded_pass` + деструктивное `well_formed` → `contradiction: true`, confidence ≤ 0.50;
3. `verified` (LL(k)-таблица / Lean без sorry) → confidence может быть 0.98;
4. только `well_formed` деструктивное доказательство → вердикт допустим, confidence ≤ 0.60;
5. reg: `test_result.fail` при `non_regular` → не `failure 0.0`, а R6.

# tfl_deep_agent — implementation contract

Full architecture (approved by the user 2026-11-07): `tfl_deep_agent/docs/architecture.html`.
This file is the short, binding contract for implementation. Where the two differ, this file wins.

## Goal

A single autonomous agent on `deepagents` (LangChain) that solves Theory of Formal Languages tasks
(REG / CFL / DCFL / LL(k)). It is a **separate approach** that lives next to the four existing
pipelines and does not replace them. It takes a task as text, PDF or image, plans by itself, picks
tools and models, spawns subagents and parallel workflows within a budget from settings, and produces
a report from a template that a human approves (HITL).

## Non-negotiables

1. **Work only on branch `feat/deep-agent`.** Do not push, merge or switch branches.
2. **Do not modify** `pumping_lemma/`, `reverse_morfism/`, or the four pipeline packages
   (`agent_system/`, `cfl_system/`, `dcfl_system/`, `ll_system/`). Import from them only. If a helper
   is missing, write it inside `tfl_deep_agent/`. Allowed outside the package: `pyproject.toml`
   (`[deep]` extra and the `tfl-deep` script), `ui_server/` (P7), `tfl_eval/` (P8 adapter),
   root `README.md` / `CLAUDE.md` / `.gitignore`.
3. **Import direction**: `tfl_deep_agent` imports the four packages. `ui_server` and `tfl_eval` may
   import `tfl_deep_agent`. Nothing imports `tfl_deep_agent` from the four packages.
4. **No live API calls, ever, during development.** No `--live`, do not load `.env`, do not set
   `ANTHROPIC_API_KEY`. Every test uses fake or scripted chat models (`GenericFakeChatModel`,
   `FakeMessagesListChatModel` or a local scripted `BaseChatModel`) or recorded replays. The root
   `conftest.py` strips the key and stubs `anthropic.Anthropic`, and it must stay effective for
   langchain-anthropic as well.
5. **Theory text** in prompts and skills is quoted or condensed from `docs/THEORY.md` (statements
   marked [проверено]) and the `tz_*.md` specs. Do not invent lemma formulations. Theory text gets
   an adversarial Opus review before it is committed.
6. **Trust levels and confidence caps** follow `docs/VERDICT_POLICY.md` (refuted / verified /
   bounded_pass / well_formed / not_verified; caps 0.98 / 0.85 / 0.55 / 0.40). Reuse
   `agent_system/lib/result_verdict.py` where possible. The model's self-assessment never raises
   confidence.
7. **Commits**: no `Co-Authored-By`, no "Generated with Claude Code", no session links.
8. **Docker-dependent tests** are skipped cleanly when Docker is unavailable.

## Resolved decisions (user, 2026-11-07)

- One agent for all four classes. Old pipelines are NOT exposed to the agent as tools.
- Input: text, PDF or image (PNG / JPG / WebP). The `intake` subagent transcribes it, and the
  agent builds IR itself when it needs oracles.
- HITL 1 (after transcription + IR) is ON by default. HITL 2 (on `submit_report`) is ON. HITL on
  `execute` is OFF by default.
- Dynamic subagents (`spawn_subagent`) and dynamic workflows (`run_workflow`, compiled to a
  LangGraph `StateGraph` with `Send` fan-out). The model for each is chosen by the agent from
  `models.allowed` in settings (haiku / sonnet / opus).
- Money limits live in settings: `per_task_usd` 10.00 (user, 2026-11-08; was 5.00), `per_day_usd` 20.00,
  `per_subagent_max_usd` 2.00, `reserve_for_report_usd` 1.00 (user, 2026-11-08; was 0.30). The budget is hierarchical
  (task → subagents → workflow branches) and checked before each model call (worst case: input
  tokens + `max_tokens` at config prices). `max_tokens` of every budgeted call is derived from the
  remaining budget of its scope (user, 2026-11-08): min(role ceiling from `config.py`,
  floor((remaining − worst-case input cost) / output price)), refused below a 4096-token floor.
  When only the reserve is left, the agent must submit its report (that call's `max_tokens` comes from
  the reserve); if it does not, the renderer produces a partial report with status `budget_exhausted`.
- Sandbox code output caps at trust `well_formed`. `bounded_pass` is only for whitelisted oracle tools.
- Opus is allowed but needs a `reason` string, which is logged (`opus_needs_reason: true`).
- Basic UI: a "Deep Agent" tab in the existing TFL Lab (`ui_server`).
- Report templates `full_proof`, `exam_solution`, `short_verdict`, `lean_appendix`. Their structure
  follows the golden examples `docs/examples/reg_grammar_SaSb_lean_proved/` and
  `docs/examples/cfl_ticket50_w1bw2w3_lean_proved/`. The ticket-50 informal proof cites a known
  wrong p=4 instance, and that case becomes a regression test for the critic.
- The evidence block and trust labels in a report are generated by code, not by the model.

## Models

`tfl_deep_agent/config.py` mirrors the four existing `config.py` files: Opus 5.5 `claude-opus-5-5`,
Sonnet 5.5 `claude-sonnet-5-5`, Haiku 5.5 `claude-haiku-5-5`, the same prices and the same EFFORT /
MAX_TOKENS conventions. `TFL_MODEL_OVERRIDE` forces every role and every ad-hoc subagent to that model.
`TFL_MAX_CONCURRENCY` uses the same shared semaphore semantics as `agent_system/lib/llm_client.py`.

| P4 | `spawn_subagent`, `run_workflow`, `model_policy`, `budget_status` | a mock workflow with 3 parallel branches and a judge stays in budget; a disallowed model, excessive depth or a cycle is refused with a clear error |

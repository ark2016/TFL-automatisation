# tfl_deep_agent

One deepagents (LangChain) agent for REG / CFL / DCFL / LL(k) tasks, next to the four pipelines.
- Usage, CLI, settings, budget, HITL, sandbox, UI and eval: `README.md`.
- Binding contract: `PLAN.md`. Where `PLAN.md` and `docs/architecture.html` differ, `PLAN.md` wins.
- Phase notes, decisions and open points: `DEV_NOTES.md`. Read it before you change a module, and append your
  decisions and deviations under your own phase heading.
- Python: the interpreter on the `Python:` line of `DEV_NOTES.md` (`.venv/Scripts/python`, with the `[deep]` extra
  installed into the main `.venv`).

## Rules

- **No live API calls during development.** Do not pass `--live`, do not load `.env` and do not set
  `ANTHROPIC_API_KEY`. Tests use scripted or fake chat models only (`agent.ScriptedChatModel` and
  `scripted_model_factory`, `GenericFakeChatModel`, `FakeMessagesListChatModel`). The root `CLAUDE.md` live-run
  rule applies to this agent too: a live run only on the user's explicit request with an agreed budget, Haiku only
  (`TFL_MODEL_OVERRIDE=claude-haiku-5-5`), with the estimated cost stated first.
- **Import direction.** `tfl_deep_agent` imports from `agent_system`, `cfl_system`, `dcfl_system` and `ll_system`;
  they never import it (`tests/test_skeleton.py` checks this). `ui_server` and `tfl_eval` may import
  `tfl_deep_agent`.
- **Read-only packages.** Do not edit `pumping_lemma/`, `reverse_morfism/` or the four pipeline packages. If a
  helper is missing, write it inside `tfl_deep_agent/`. Allowed outside the package: `pyproject.toml` (the `[deep]`
  extra and the `tfl-deep` script), `ui_server/`, `tfl_eval/`, and the root `README.md`, `CLAUDE.md` and `.gitignore`.
- **Theory text.** Text in prompts and skills is quoted or condensed from `docs/THEORY.md` (statements marked
  [проверено]) and the `tz_*.md` specs. Never invent a lemma formulation. Theory text gets an adversarial Opus
  review before it is committed.
- **Trust is code's job.** Trust levels and confidence caps follow `docs/VERDICT_POLICY.md`. The model never sets
  them; `submit_report` has no trust or confidence fields (`extra="forbid"`). The evidence block of a report is
  generated by code.
- **Docker tests** must skip cleanly when Docker, the daemon or the image is missing.
- **Commits.** No `Co-Authored-By`, no "Generated with Claude Code" and no session links.

## Tests

```bash
.venv/Scripts/python -m pytest -q tfl_deep_agent/tests           # this package
.venv/Scripts/python -m pytest -q -n 4 tfl_deep_agent/tests      # faster
.venv/Scripts/python -m pytest -q                                # whole repo (pyproject testpaths)
```

- A test directory outside this package that builds the agent must import the fixtures of `tests/guard.py` in its
  `conftest.py`. `tests/test_network_guard.py` fails otherwise.
- Mock scripts (`examples/mock/*.json`, `tests/hitl_scripts.py`) are keyed by role. `spawn:<name>` and
  `workflow:<step id>` are the keys for ad-hoc children; any other unknown key is an error.
- `tests/test_docs.py` keeps `README.md` and the root docs in step with the CLI, the settings defaults and the
  shipped files. Update the docs when you change one of those.
- The full suite on this host has Docker-Lean compile failures in the pipeline packages, caused by the flaky Docker
  daemon (`OCI runtime ... connection reset by peer`). They are recorded at every gate in `DEV_NOTES.md` and are
  not caused by this package.

## Pitfalls

- Editing these files through a bash heredoc that runs Python mangles backslashes; use the Edit tool.
- Files written on this host have CRLF line endings; do not reformat files outside your change.
- `regex_to_dfa` runs in a spawned process. From a `python -` (stdin) script it times out, because the child
  cannot re-import `<stdin>`. Files, pytest and the CLI are fine.
- The runners (`hitl.start_run` / `resume_run`) do not open a sandbox yet, so CLI and UI runs have no `coder`.
  Turning the sandbox on for user runs is a behaviour change that needs the user's decision.
